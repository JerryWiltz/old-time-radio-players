# How the Radio Players Work

The files ending in `-player.html` are standalone web pages for listening to old-time radio episodes. Each player contains its HTML structure, visual styling, episode list, and JavaScript behavior in a single file.

## Project Structure

- `*-player.html` files are the usable radio players.
- `raw/` contains unchanged snapshots of the original Old Radio World pages.
- Audio files are not stored in this vault. They are streamed from [Old Radio World](https://www.oldradioworld.com/).

## Page Structure

Each player has three main interface sections:

1. A heading containing the radio show's name.
2. A sticky player panel containing the current episode title, the browser's native audio controls, Previous and Next buttons, and playback options.
3. An ordered episode list whose entries behave as buttons.

The player panel uses `position: sticky`, so it remains visible at the top of the page while the episode list is scrolled.

## Main HTML Elements

The JavaScript locates important elements by their IDs:

| Element | Purpose |
| --- | --- |
| `audio` | The browser's native audio player |
| `nowPlaying` | Displays the selected episode number and title |
| `episodeList` | Receives the episode buttons generated by JavaScript |
| `previous` | Selects the preceding episode |
| `next` | Selects the next sequential or random episode |
| `shuffle` | Switches Next and automatic continuation to random selection |
| `autoNext` | Controls whether another episode starts after the current one ends |

The IDs are part of the connection between the HTML and JavaScript. Renaming an ID in the HTML also requires changing its `document.querySelector()` call.

The `<audio>` element uses `preload="metadata"`. This asks the browser to obtain enough information to display properties such as duration without intentionally downloading the complete recording before playback.

## Episode Data

The JavaScript begins with the remote media directory:

```js
const base = "https://www.oldradioworld.com/media/";
```

The `files` array contains the exact MP3 filenames extracted from the corresponding source page in `raw/`:

```js
const files = [
  "Superman 1940-02-12 The Baby From Krypton.mp3",
  // More episodes...
];
```

### What a Regular Expression Is

A **regular expression**, often shortened to **regex**, is a small pattern used to find text. In these players, regular expressions remove predictable pieces of an MP3 filename so that the listener sees a cleaner episode title.

A JavaScript regular expression is written between forward slashes:

```js
/text to find/
```

This is different from a quoted string. The slashes tell JavaScript to interpret the contents as a search pattern.

For example, the Superman player starts with this filename:

```text
Superman 1940-02-12 The Baby From Krypton.mp3
```

It cleans that filename with:

```js
file
  .replace(/^Superman \d{4}-\d{2}-\d{2} /, "")
  .replace(/\.mp3$/, "")
```

The first `replace()` removes `Superman 1940-02-12 `, and the second removes `.mp3`. The final title is:

```text
The Baby From Krypton
```

Here is what the special regex notation means:

| Pattern part | Meaning |
| --- | --- |
| `/` | Begins or ends the regular expression |
| `^` | Match only at the beginning of the text |
| `Superman ` | Match those exact letters followed by a space |
| `\d` | Match one digit from 0 through 9 |
| `{4}` | Repeat the preceding match four times |
| `{2}` | Repeat the preceding match two times |
| `-` | Match a normal hyphen |
| `\.` | Match an actual period; a bare `.` has a special regex meaning |
| `$` | Match only at the end of the text |

Therefore, `\d{4}-\d{2}-\d{2}` means “four digits, a hyphen, two digits, a hyphen, and two digits”—the shape of a date such as `1940-02-12`.

The empty string `""` passed as the second argument to `replace()` means “replace the matched text with nothing,” which removes it.

### Regular Expression Flags

Letters after a regex's closing slash change how it searches:

| Flag | Meaning |
| --- | --- |
| `i` | Ignore uppercase/lowercase differences |
| `g` | Find every match instead of stopping after the first |

For example:

```js
/\.mp3$/i
```

This finds `.mp3` at the end of a filename regardless of whether it is written as `.mp3`, `.MP3`, or `.Mp3`.

Not every text replacement needs a regular expression. Night Beat uses this ordinary string replacement:

```js
.replaceAll("%27", "'")
```

It simply replaces every literal `%27` in the display title with an apostrophe.

The array is transformed into `episodes`. Each episode has a readable title and a complete URL:

```js
const episodes = files.map((file) => ({
  title: /* filename with the show name, date, and .mp3 removed */,
  url: base + encodeURIComponent(file)
}));
```

`encodeURIComponent()` safely converts spaces and other filename characters for use in a web address.

### Internet Archive Filename Encoding

The Night Beat player uses a slightly stricter encoder:

```js
url: base + encodeURIComponent(file).replace(
  /[!'()*]/g,
  (character) => `%${character.charCodeAt(0).toString(16).toUpperCase()}`
)
```

In the regular expression `/[!'()*]/g`, the square brackets mean “match any one character from this list.” The `g` flag means to find every occurrence. In plain language, the code says: find every `!`, apostrophe, `(`, `)`, or `*`, then convert each one to its hexadecimal URL form.

`encodeURIComponent()` leaves those punctuation characters unchanged. The extra replacement converts them to hexadecimal URL escapes so the generated address matches Internet Archive's file links.

Several Night Beat filenames contain `%27` as literal filename text. Encoding the percent sign turns this into `%2527` in the request URL. This is intentional: `%25` represents a literal percent sign, while the remaining `27` remains part of the stored filename. Display titles replace `%27` with an apostrophe for readability without changing the remote filename.

The Night Beat title cleanup uses the case-insensitive `i` flag described above when removing `.mp3`, because some source files use `.Mp3` capitalization.

## Building the Episode List

The code loops over `episodes` and creates a list item and button for each entry. Clicking an episode button calls `loadEpisode(index)`, where `index` identifies that episode's position in the array.

The list is generated by JavaScript when the page loads, so the episode filenames only need to be maintained in one place.

The relevant DOM-building sequence is:

```js
const item = document.createElement("li");
const button = document.createElement("button");
button.className = "episode";
button.type = "button";
button.textContent = `${index + 1}. ${episode.title}`;
button.addEventListener("click", () => loadEpisode(index));
item.append(button);
list.append(item);
```

Using `textContent` rather than HTML markup ensures filenames are displayed as text instead of being interpreted as page elements. Setting `type="button"` also prevents unexpected form-submission behavior if the interface is ever placed inside a form.

## Loading and Playing an Episode

`currentIndex` records the selected episode. It starts at `-1`, meaning that no episode has been selected.

The `loadEpisode(index, play)` function performs the main work:

1. It normalizes the requested index so playback wraps around at either end of the list.
2. It assigns the episode's remote URL to the `<audio>` element.
3. It updates the “now playing” text.
4. It highlights the selected episode button.
5. It scrolls the selected entry into view when necessary.
6. It asks the browser to begin playback.

The call to `audio.play()` catches rejected playback promises. Browsers sometimes block playback that was not initiated by a user action, so the page avoids displaying an unhandled JavaScript error when that happens.

### Index Wraparound

`loadEpisode()` normalizes an index with this expression:

```js
currentIndex = (index + episodes.length) % episodes.length;
```

Adding the array length before applying the remainder operator keeps a preceding index from becoming negative. For example, requesting `-1` in a 74-episode player becomes index `73`, which is the final episode.

The page uses zero-based array indexes internally but displays `currentIndex + 1` to listeners, so the visible list begins at episode 1.

### Updating the Interface

After changing the audio source, `loadEpisode()` updates every episode button's `active` class:

```js
document.querySelectorAll(".episode").forEach((button, i) =>
  button.classList.toggle("active", i === currentIndex)
);
```

Only the selected button receives the class. CSS gives that button a darker background, and `scrollIntoView({ block: "nearest" })` moves it only when needed rather than forcing it to the top of the window.

## Previous and Next

The Previous button selects the preceding item in the episode array. From the first episode, it wraps around to the last episode.

The Next button calls `getNextIndex()`. With Shuffle disabled, this returns the following episode and wraps from the last episode to the first.

Previous remains sequential even while Shuffle is enabled.

If no episode has been selected, pressing Next starts with the first episode. Pressing Previous before making a selection loads the final episode because its handler treats an unset or first index as a request to wrap backward.

## Shuffle

When the Shuffle checkbox is enabled, `getNextIndex()` chooses a random array index:

```js
let nextIndex;
do nextIndex = Math.floor(Math.random() * episodes.length);
while (nextIndex === currentIndex);
```

The loop prevents the currently playing episode from being selected again immediately. A special check avoids this loop when a player contains fewer than two episodes.

Shuffle affects the Next button and automatic continuation.

This implementation chooses independently each time. It prevents an immediate repeat, but it does not maintain a shuffled history or guarantee that every episode will play once before another is repeated.

## Automatic Continuation

The audio element emits an `ended` event when an episode finishes. If **Play next automatically** is checked, the handler obtains the next sequential or shuffled index and passes it to `loadEpisode()`:

```js
audio.addEventListener("ended", () => {
  if (autoNext.checked) loadEpisode(getNextIndex());
});
```

Automatic continuation is enabled by default. Clearing the checkbox makes the player stop when the current episode ends.

The continuation begins only after the audio element reports that playback ended normally. Pausing, seeking, a network failure, or closing the page does not trigger the `ended` handler.

## Event Flow

The normal playback path is:

1. The listener clicks an episode or navigation button.
2. The click handler determines an array index.
3. `loadEpisode()` changes the audio URL and updates the interface.
4. The browser streams and plays the remote MP3.
5. The audio element emits `ended` when playback completes.
6. If automatic continuation is enabled, `getNextIndex()` selects another episode and the cycle returns to `loadEpisode()`.

There is no background service, server-side code, database, framework, or build process. Closing or refreshing the page resets `currentIndex` and all checkbox state to their HTML defaults.

## Styling

All CSS is embedded in each player's `<style>` element. The layout uses a maximum content width of 760 pixels while leaving a 16-pixel margin on narrow screens. Flexbox allows the player controls to wrap when there is not enough horizontal space.

The page declares `color-scheme: dark`, uses high-contrast foreground colors, and relies on the browser's native accessible audio controls. Episode entries are actual `<button>` elements, so they can receive keyboard focus and be activated without a mouse.

Because the CSS and JavaScript are duplicated in every player, a shared behavior change currently needs to be applied and tested in every `*-player.html` file.

## Audio Streaming

Selecting an episode does not permanently download its MP3 into this vault. Chrome requests the recording from Old Radio World and may temporarily cache some or all of it while it plays. The remote site must remain available, and its filenames must remain unchanged, for these players to work.

Night Beat streams from Internet Archive instead of Old Radio World. Its base address is:

```text
https://archive.org/download/NightBeataccurate/
```

The source hosts support byte-range requests, allowing the browser to seek through a recording without first transferring the entire MP3. Playback can still fail temporarily because of network availability, remote throttling, a renamed source file, or a browser media-decoding problem.

## Local Browser Access

The players are local HTML files inside the ChromeOS Linux/Crostini environment. Opening them through **Linux files** grants Chrome access to the selected file. A manually entered `file:///home/...` bookmark may not work from ChromeOS because that Linux path belongs to the Crostini container.

For a durable browser bookmark, open the working page through **Linux files** and bookmark the address Chrome actually displays. Serving the vault through a small local HTTP server is another option when stable `http://localhost/...` addresses are needed.

## Adding Another Show

To add a show, save its original PHP page in `raw/`, extract its MP3 links in source order, and create another root-level player from an existing player template. Change the page title, heading, filename array, and title-cleanup expression for the new show. Then verify that the JavaScript parses and that every MP3 filename exactly matches the downloaded source page.

The detailed repeatable procedure is recorded in [AGENTS.md](AGENTS.md).
