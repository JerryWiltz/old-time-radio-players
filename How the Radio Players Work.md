# How the Radio Players Work

The files ending in `-player.html` are standalone web pages for listening to old-time radio episodes. Each player contains its HTML structure, visual styling, episode list, and JavaScript behavior in a single file.

## Project Structure

- `*-player.html` files are the usable radio players.
- `raw/` contains unchanged snapshots of the original Old Radio World pages.
- Audio files are not stored in this vault. They are streamed from [Old Radio World](https://www.oldradioworld.com/).

## Page Structure

Each player has three main interface sections:

1. A heading containing the radio show's name.
2. A sticky player panel containing the current episode title, the browser's native audio controls, Previous and Next buttons, and playback options.
3. An ordered episode list whose entries behave as buttons.

The player panel uses `position: sticky`, so it remains visible at the top of the page while the episode list is scrolled.

## Episode Data

The JavaScript begins with the remote media directory:

```js
const base = "https://www.oldradioworld.com/media/";
```

The `files` array contains the exact MP3 filenames extracted from the corresponding source page in `raw/`:

```js
const files = [
  "Superman 1940-02-12 The Baby From Krypton.mp3",
  // More episodes...
];
```

The array is transformed into `episodes`. Each episode has a readable title and a complete URL:

```js
const episodes = files.map((file) => ({
  title: /* filename with the show name, date, and .mp3 removed */,
  url: base + encodeURIComponent(file)
}));
```

`encodeURIComponent()` safely converts spaces and other filename characters for use in a web address.

## Building the Episode List

The code loops over `episodes` and creates a list item and button for each entry. Clicking an episode button calls `loadEpisode(index)`, where `index` identifies that episode's position in the array.

The list is generated by JavaScript when the page loads, so the episode filenames only need to be maintained in one place.

## Loading and Playing an Episode

`currentIndex` records the selected episode. It starts at `-1`, meaning that no episode has been selected.

The `loadEpisode(index, play)` function performs the main work:

1. It normalizes the requested index so playback wraps around at either end of the list.
2. It assigns the episode's remote URL to the `<audio>` element.
3. It updates the “now playing” text.
4. It highlights the selected episode button.
5. It scrolls the selected entry into view when necessary.
6. It asks the browser to begin playback.

The call to `audio.play()` catches rejected playback promises. Browsers sometimes block playback that was not initiated by a user action, so the page avoids displaying an unhandled JavaScript error when that happens.

## Previous and Next

The Previous button selects the preceding item in the episode array. From the first episode, it wraps around to the last episode.

The Next button calls `getNextIndex()`. With Shuffle disabled, this returns the following episode and wraps from the last episode to the first.

Previous remains sequential even while Shuffle is enabled.

## Shuffle

When the Shuffle checkbox is enabled, `getNextIndex()` chooses a random array index:

```js
let nextIndex;
do nextIndex = Math.floor(Math.random() * episodes.length);
while (nextIndex === currentIndex);
```

The loop prevents the currently playing episode from being selected again immediately. A special check avoids this loop when a player contains fewer than two episodes.

Shuffle affects the Next button and automatic continuation.

## Automatic Continuation

The audio element emits an `ended` event when an episode finishes. If **Play next automatically** is checked, the handler obtains the next sequential or shuffled index and passes it to `loadEpisode()`:

```js
audio.addEventListener("ended", () => {
  if (autoNext.checked) loadEpisode(getNextIndex());
});
```

Automatic continuation is enabled by default. Clearing the checkbox makes the player stop when the current episode ends.

## Audio Streaming

Selecting an episode does not permanently download its MP3 into this vault. Chrome requests the recording from Old Radio World and may temporarily cache some or all of it while it plays. The remote site must remain available, and its filenames must remain unchanged, for these players to work.

## Adding Another Show

To add a show, save its original PHP page in `raw/`, extract its MP3 links in source order, and create another root-level player from an existing player template. Change the page title, heading, filename array, and title-cleanup expression for the new show. Then verify that the JavaScript parses and that every MP3 filename exactly matches the downloaded source page.

The detailed repeatable procedure is recorded in [AGENTS.md](AGENTS.md).
